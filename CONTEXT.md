# LLM Interview

A showcase project for comparing AI agent generation quality: pi.dev builds small web projects under different Question / Model combinations, every run is fully archived (transcript + artifact), and a static dashboard lets viewers compare the results side by side.

## Language

**Question**:
A directory under `question/` (the directory name serves as the Question's unique name) containing `intent.md` (the task intent) plus optional `spec.md` and `tickets.md` (detailed spec and task breakdown produced from the intent via the grilling workflow). Deliberately omitting spec/tickets is a test scenario that probes the model's own planning ability.
_Avoid_: task, prompt file

**Run**:
A single execution: one Question executed once by pi.dev under one model + parameter combination. The smallest unit of comparison. A Run's working directory is an isolated temp area outside the repo — the model cannot see the project's AGENTS.md, other Sessions' artifacts, or any project file; artifacts and transcript are collected into the archive afterwards.
_Avoid_: execution, combo run

**Pi Invocation**:
One invocation of the pi agent within a Run: either the execution of one ticket (when the Question's tickets.md parses into ≥ 2 tickets) or an evaluation pass arbitrating a dirty invocation. Each invocation gets a fresh session and context; all invocations of a Run share one isolated workdir. Distinct from pi's internal *turn* — one model iteration within an invocation, counted by `maxTurns` (ADR 0003).
_Avoid_: step, phase, runner turn

**Session**:
The complete archive unit of a Run, stored in a per-Run directory under `session/`, containing the transcript (JSONL), the Artifact, and `run.json` — never separated.
_Avoid_: transcript, conversation log, output (never call the artifact alone "output")

**Artifact**:
The web product generated by pi in one Run: exactly three files — `index.html`, `style.css`, `script.js`. CSS/JS are not inlined, not minified/obfuscated, kept readable, with no extra files. Part of a Session; rendered directly in the dashboard via iframe.
_Avoid_: output, result, product

**Model Registry**:
A manually maintained configuration document in the project recording each available model's server-side sampling parameters (thinking, temp, top_k, top_p, etc.). These parameters are copied verbatim into each Run's `run.json`.
_Avoid_: models config, model list

**Combo**:
The full parameter identity of a Run: Question + Model. The Runner does not vary any model parameters itself; the parameters recorded in the Model Registry are a snapshot of the server-side configuration at execution time, written into `run.json` as documentation. Parameter comparison is deferred to the future.
_Avoid_: parameter combination (colloquially fine, but use Combo in documents)

**Manifest**:
The mapping JSON generated at dashboard build time; the index of Session data in dist: comboId → metadata of the latest Run (question, model, parameter snapshot, time) and file paths. Only the latest Run of each Combo is published; the repo's `session/` keeps full history.
_Avoid_: index.json, mapping

**Dashboard**:
The statically published site (GitHub Pages) aggregating all Sessions, letting viewers compare Artifact quality and transcripts across Question / Model combos. Artifact-first; the process view is expandable. On mobile (viewport ≤ 768px) it degrades to a transcript-first experience: Artifact iframes render read-only and cannot be expanded (ADR 0008).
_Avoid_: site, viewer
