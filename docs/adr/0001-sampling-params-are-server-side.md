# Sampling parameters are server-side; the Runner records but never controls them

pi's CLI, settings.json, and models.json offer no entry point for sampling parameters such as temperature / top_k / top_p — these are decided by the llama.cpp server-side startup configuration and cannot vary per request from the client. The Runner's comparison matrix is therefore defined as Question × Model; model parameters are recorded as snapshots via the manually maintained Model Registry and written into each Run's run.json, for display and archival purposes only. Automated parameter comparison dimensions (e.g. temp/top_k/top_p sweeps, thinking on/off) are deferred until the prerequisites exist (multiple server instances differentiated by port, or pi support for request-level parameters).
