# Mobile dashboard is transcript-first with read-only artifact previews

The Dashboard's desktop experience is Artifact-first: every ComboCard renders an interactive sandboxed iframe, and `⛶ Expand` opens a fullscreen SessionView with a large Artifact stage. On mobile (viewport ≤ 768px, covering phones and portrait tablets) this breaks down: iframes trap touch scrolling, side-by-side panels do not fit, and interacting with a generated Artifact on a small screen has little value for comparison. Mobile is therefore a deliberately **reduced, transcript-first** experience, implemented with CSS only (`@media (max-width: 768px)`) — no JS `matchMedia` branching and no route guards.

On mobile, ComboCard iframes stay rendered but are locked read-only via `pointer-events: none` (touches fall through to the page), with a one-line hint (`Live preview · interactive on desktop`); the `⛶ Expand` link is hidden and the transcript toggle becomes the primary action. The `#/session/...` route is deliberately **not** blocked: direct URL access renders a stacked layout with the iframe stage hidden (`display: none`) and the transcript panel full-width as the main content, so shared or refreshed links never dead-end.

Two trade-offs are accepted. Locked iframes still fully load on mobile (a static preview was judged more valuable than the bandwidth savings of `v-if` removal; `loading="lazy"` is a possible follow-up but out of scope). And hiding the SessionView stage with `display: none` rather than not rendering it keeps the implementation CSS-only at the cost of loading one iframe the user never sees. A build-time screenshot pipeline was considered and rejected as disproportionate complexity for a static showcase.
